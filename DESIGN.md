# Piko Design

The app icon uses the Little Lookout: a compact resting bird that expresses quiet, continuous observation rather than speed, aggressive cleanup, or a generic initial. A deep-petrol silhouette, pale-jade wing and small apricot beak sit directly on a full-bleed celadon field. Broad shapes and shallow satin lighting take priority over decorative extrusion. Native Icon Composer supplies the mask; never nest a pre-rounded tile inside it. This identity does not recolor the monitoring UI or change the menu-bar template symbol.

The user checks load beside their work on a Mac mini in changing daylight and evening light. Appearance has three persistent choices: cold, warm and dark. Cold/warm force Aqua native controls; dark forces Dark Aqua. Legacy light/system preferences migrate to cold and legacy dark stays dark. The current direction is the compact, information-first Mole 1.13.0 reference supplied by the user, without copying its branding or claiming its complete feature set.

Use genuine AppKit vibrancy for the shell, not a simulated web glass overlay. Light cards are opaque white: no material or colored wash on each card. Cold uses a porcelain-white shell, graphite text, cobalt navigation/CPU, muted copper memory/upload and teal GPU/downloads. Warm keeps a near-white shell with a restrained warm undertone, terracotta navigation/CPU, slate-blue memory/upload and teal transfers. Dark uses ink surfaces with soft mint, slate blue and teal. No purple. Define immutable OKLCH palettes and inject the selected palette through the SwiftUI environment so cards, text, symbols and charts update together. The shell tint is 97% opaque to resist wallpaper color contamination. Reduced Transparency replaces materials with solid themed surfaces.

Color hierarchy: the brand tone owns navigation and CPU; supporting and transfer tones carry secondary metrics. Tile labels use secondary ink with only their small icon colored. Warning and positive are independent semantic roles, so healthy states stay green even in the warm theme. Light shell/card L values are about 0.974/0.999; dark shell/card L values are 0.19/0.27. Secondary text has its own high-contrast token rather than uncontrolled gray opacity. Palette tests cover all three themes' text/control and header contrast, preference migration/reload and OKLCH neutral conversion; visual QA checks actual material composites and live theme switching.

SF Pro and rounded SF numerals carry the interface. Native window/popover clipping and a single capsule navigation retain macOS behavior. No ornamental chart data, wallpaper animation or persistent metric logs.

The user supplied Mole 1.13.0 status, menu-bar and software screenshots and rejected the branded header: remove the large logo/title/time block, large activity rings and eight-icon navigation. Use 12-point corner radii, no card shadows, small inline SF Symbols, 10-13-point supporting text and 23-26-point values. Keep the existing three palettes and restrained material treatment.

The 380-point menu-bar HUD has a fixed, approximately 58-point header: a 30-point waveform tile, small Piko name and hardware line, live/paused state and actual system status. No large title, clock, repeated status block or invented health score. Six compact CPU/GPU/memory/disk/network/thermal tiles, a power row, five high-usage processes and quick actions fit in a screen-height-capped panel. The 980-point desktop window has a single centered navigation capsule (status, cleanup, software, analysis, tools), a separate settings control, eight status tiles and a larger process table. Clicking metrics opens existing detailed views; the HUD does not try to contain maintenance workflows.

Charts use linear interpolation to preserve measured peaks, round caps and joins, 1.15-point sparkline strokes and 1.5-point detail strokes. Single series get only a faint under-fill; dual series have no fill and a dashed secondary line with explicit line-style labels. Keep small vertical plot insets so peaks do not touch the card edge. Core meters are narrow capsules on neutral tracks instead of wide blocks. No smoothing that invents intermediate extrema, glows or ornamental markers.

Both the compact header and desktop toolbar expose a 28-point appearance button. A single click cycles cold, warm and dark, with the current mode expressed by a snowflake, sun or moon and an accessible value. Reuse the settings binding so every surface updates and the preference persists immediately; no intermediate menu is required.

Settings picker rows share a 150-point trailing control column aligned with the switch rows and the card's content edge. On macOS 26, opt native menu pickers into flexible button sizing so their actual bezels fill that column instead of centering unequal content-sized buttons within equal outer frames. Keep native selection, keyboard and accessibility behavior.

The macOS status item keeps its native template waveform and button behavior, without identity dots before metric labels. Defaults are 11-point medium labels and 12-point semibold tabular values. Labels and values share a baseline, separated by one en space (half the label font size, 5.5 points by default), with no hyphen. The settings preview uses the same half-em gap. Never automatically shrink type to save width. Thin, low-contrast separators with en-space gutters divide enabled groups. Network arrows are secondary neutral, with a separate inner gap and no hyphen. Disabled modules leave no separators; disabling every module retains the icon-only status item.

Only numeric readouts carry alert colors. CPU, GPU and memory usage turn yellow at 80 percent and red at 90 percent. System memory pressure can escalate, but never downgrade, that level. Startup disk available capacity turns yellow at 15 percent remaining and red at 10 percent remaining. Network throughput stays neutral because speed alone is not a health signal. Missing readings stay neutral; readings returning below thresholds recover automatically. Native menu-bar appearance controls the adaptive yellow/red contrast independently of the panel theme. Labels and disk suffixes remain neutral. The settings panel explains the thresholds and its CPU preview shares the status-item severity resolver.

The settings panel exposes separate label and numeric typography rows: system, rounded or monospaced family; integer sizes from 9 to 16 points; and an independent native bold checkbox. Unchecked uses medium, checked uses semibold. Numeric glyphs remain tabular in every family. A real CPU reading previews both roles using the same font resolver as the status item. Changes apply immediately, including while sampling is paused, and persist under separate keys without modifying other settings. Invalid stored values fall back safely. Group separators stay optically centered as font sizes change.

The disk module shows startup-volume available capacity with an explicit available label, rather than another ambiguous percentage. Prefer the macOS Data volume, fall back to the root volume, and never substitute an external drive when the startup reading is unavailable. It defaults on with its own persisted settings switch. The native variable-length status item expands to fit all enabled modules without reducing type or group spacing.

The standalone workspace uses regular application activation with a Dock entry and native application/window menus. Its window is a managed primary window, not a transient utility. Menu-bar-only operation remains accessory mode; closing or collapsing the workspace returns to that mode. Foreground requests restore the explicitly requested window, including one ordered out by the system, but never undo deliberate close, hide, collapse or minimization. Ordinary deactivation does not raise the window or steal focus. Folder selection is an asynchronous sheet attached to the main window, not an independent application-modal panel. Window lifecycle transitions record only activation/visibility flags in the system log for permission-dialog diagnosis, never scanned paths or file contents. Directory scans drain temporary Foundation metadata objects for each enumerated entry and each subtree so permission pauses and long scans do not retain an entire tree of autoreleased objects.

Cleanup and application screens are review-first lists with explicit paths and sizes. Disk analysis uses a proportional binary treemap of the largest twelve direct children with a complete result list beneath it. Partial scans, protected/cloud content, unreadable entries and traversal limits remain visible. Long operations run off the main actor and can be cancelled; the monitor keeps sampling independently. Never show sample metrics, claimed cleanup totals or fake hardware temperatures.
